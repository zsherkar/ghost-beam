# Artifact Schema

Ghost Beam produces local JSON/Markdown artifacts for auditability. These are synthetic demo artifacts, not facility records.

## DecisionRecord

Returned by `/plan/evaluate` and `/experiment/evaluate`.

Schema:

- Runtime schema endpoint: `GET /artifacts/schemas/decision-record`
- Repository schema file: `backend/ghostbeam/artifacts/schemas/decision_record.schema.json`
- Current schema version: `0.1.0`

Key fields:

- `scenario_id`: active synthetic scenario
- `current_settings`: machine setting snapshot
- `safe_signals`: safe process-variable snapshot
- `proposed_action`: action intent, source, and delta settings
- `virtual_diagnostic`: predicted quality, beam sizes, loss, uncertainty, OOD score, trust state, and reasons
- `vision_diagnostic`: beam-profile image-moment metrics and semantic labels
- `elog_hits`: top retrieved synthetic operator-log matches
- `gate_decision`: deterministic policy result, reasons, approved deltas, blocked deltas, and safe next step
- `simulated_outcome_if_applied`: synthetic projected beam outcome if the action were applied

## GuidedDemoReport

Generated by `POST /experiment/report/generate` during the Drifted Twin Test, with frontend fallback if the backend is unavailable. Backend-generated reports are persisted locally under `backend/artifacts/reports/`.

Key fields:

- `report_id`
- `schema_version`
- `demo_title`
- `created_at`
- `scenario_ids_used`
- `synthetic_data_disclosure`
- `executive_summary`
- `initial_trust_metrics`
- `naive_proposal`
- `ghost_beam_decision`
- `top_elog_match`
- `calibration_event`
- `post_calibration_metrics`
- `safer_action`
- `final_decision`
- `final_beam_metrics`
- `decision_record_ids`
- `transcript`
- `report_source`
- `disclosures`

The report is downloadable as JSON and Markdown.

## Full Session Export

Generated from `/experiment/export` and enriched in the frontend.

Contains:

- backend session state
- event history
- decision records
- per-record DecisionRecord validation status
- export-level validation summary
- latest machine state
- frontend package metadata
- guided transcript if available
- guided mission report if generated
- synthetic-data disclosure
- current theme and twin-lighting settings

Recommended filename format:

```text
ghostbeam_session_YYYYMMDD_HHMMSS.json
ghostbeam_drifted_twin_report_YYYYMMDD_HHMMSS.md
ghostbeam_drifted_twin_report_YYYYMMDD_HHMMSS.json
```

## Synthetic Data Manifest

The formal data provenance manifest lives at:

```text
backend/data/synthetic_data_manifest.json
```

It documents:

- JAX transfer-matrix digital-twin generation
- PV-like machine settings
- safe signals
- hidden beam outputs
- synthetic beam-profile images
- synthetic eLog corpus size
- demo scenarios
- explicit no-real-facility-data disclosure

The same manifest is available through `GET /platform/data-manifest`.

## BenchmarkResult

Generated by `POST /benchmark/run`.

Key fields:

- `benchmark_id`
- `created_at`
- `metrics`
- `trial_table`
- `top_interventions`
- `summary`
- `synthetic_data_disclosure`

Required headline metrics include:

- total trials
- Ghost Beam approvals / small-step approvals / blocks / calibration requests / human-review decisions
- hard-limit violations prevented
- eLog conflicts caught
- average naive projected quality/loss
- average Ghost Beam projected quality/loss
- average OOD before/after calibration
- percent actions modified or blocked
- percent safe actions allowed

## EvidenceBundle

Generated by `POST /experiment/evidence-bundle`.

Key fields:

- `bundle_id`
- `session_export`
- `latest_decision_record`
- `latest_mission_report`
- `latest_benchmark`
- `synthetic_data_manifest`
- `decision_record_schema`
- `platform_adapters`
- `platform_capabilities`
- `guided_transcript`
- `top_elog_evidence`
- `README_BUNDLE.md`
- `ro-crate-metadata.json`

The current MVP exports a single JSON bundle rather than a ZIP file to avoid extra dependency and file-handling risk.
