# Artifact Schema

Ghost Beam produces local JSON/Markdown artifacts for auditability. These are synthetic demo artifacts, not facility records.

## Decision Record

Returned by `/plan/evaluate` and `/experiment/evaluate`.

Schema:

- Runtime schema endpoint: `GET /artifacts/schemas/decision-record`
- Repository schema file: `backend/ghostbeam/artifacts/schemas/decision_record.schema.json`
- Current schema version: `0.1.0`

Key fields:

- `scenario_id`: active synthetic scenario
- `current_settings`: machine setting snapshot
- `safe_signals`: safe process-variable snapshot
- `proposed_action`: action intent, source, and delta settings
- `virtual_diagnostic`: predicted quality, beam sizes, loss, uncertainty, OOD score, trust state, and reasons
- `vision_diagnostic`: beam-profile image-moment metrics and semantic labels
- `elog_hits`: top retrieved synthetic operator-log matches
- `gate_decision`: deterministic policy result, reasons, approved deltas, blocked deltas, and safe next step
- `simulated_outcome_if_applied`: synthetic projected beam outcome if the action were applied

## Ghost Beam Diagnosis

The frontend builds a human-readable diagnosis from the latest Decision Record and experiment state. It is shown in the Decision Record drawer, can be copied or exported as Markdown, and is included in backend mission-report and evidence-bundle metadata when generated from the UI.

Key sections:

- `what_happened`: proposed action and scenario context
- `why_intervened`: trust, policy, hard-limit, calibration, or eLog reason
- `evidence_used`: OOD, uncertainty, twin trust, vision label, top eLog match, risk tags, and policy rule
- `decision`: human-readable gate decision
- `action_taken`: approved, clipped, calibration requested, human review required, or blocked
- `outcome`: expected protected or recovered beam state
- `next_step`: recommended operator/demo follow-up
- `timeline`: "What Ghost Beam Did" sequence from proposal through outcome
- `markdown`: copy/export-ready diagnosis report

## Full Session Export

Generated from `/experiment/export` and enriched in the frontend.

Contains:

- backend session state
- event history
- decision records
- per-record Decision Record validation status
- export-level validation summary
- latest machine state
- frontend package metadata
- guided transcript if available
- guided mission report if generated
- synthetic-data disclosure
- current theme and twin-lighting settings

Recommended filename format:

```text
ghostbeam_session_YYYYMMDD_HHMMSS.json
ghostbeam_drifted_twin_report_YYYYMMDD_HHMMSS.md
ghostbeam_drifted_twin_report_YYYYMMDD_HHMMSS.json
```

## Synthetic Data Manifest

The formal data provenance manifest lives at:

```text
backend/data/synthetic_data_manifest.json
```

It documents:

- JAX transfer-matrix digital-twin generation
- PV-like machine settings
- safe signals
- hidden beam outputs
- synthetic beam-profile images
- synthetic eLog corpus size
- demo scenarios
- explicit no-real-facility-data disclosure

The same manifest is available through `GET /platform/data-manifest`.

## RecordedRunFixture

Recorded-run fixtures live under:

```text
backend/data/recorded_runs/
```

Endpoints:

- `GET /recorded-runs`
- `POST /recorded-runs/load`
- `POST /recorded-runs/evaluate-step`

Key files:

- `sample_recorded_drifted_twin.csv`: PV/readback trace generated from the synthetic twin
- `sample_recorded_drifted_twin_elogs.csv`: associated synthetic operator-memory rows
- `sample_recorded_drifted_twin_manifest.json`: provenance, scenario, column list, and safety disclosure

The recorded-run fixture is a synthetic replay artifact, not facility data. It demonstrates that Ghost Beam can evaluate an offline trace through the same virtual diagnostic, eLog retrieval, and policy gate used by the live synthetic twin.

## PublicDataAnalysisRecord

Public Data Mode can import a local BOOSTR-compatible CSV/Parquet slice from `backend/data/public_datasets/boostr/` and evaluate a read-only window. This does not mutate the active experiment session and never enables hardware writes.

Key fields:

- `artifact_type`: `PublicDataAnalysisRecord`
- `source_id`: `boostr`
- `run_id`
- `dataset_id`: `boostr`
- `data_source`: `public_boostr`
- `window`: start/stop/row count
- `window_start`
- `window_size`
- `detected_columns`
- `numeric_metrics`: per-signal window mean/min/max/z-score
- `anomaly_score`
- `trust_score`
- `trust_assessment`
- `decision`: `WINDOW_OK`, `ANALYZE`, or `FLAG_FOR_REVIEW`
- `recommended_action`
- `policy_language`: `Recorded public data analysis only - no writes permitted.`
- `writes_allowed`: always `false`
- `hardware_write_permitted`: always `false`
- `disclosure`: read-only public data analysis disclosure

The evidence bundle includes the BOOSTR manifest, Fermilab BPM/IPM manifest, data-source registry, and latest public-data analysis artifact when available.

## DataSourceRegistry

Returned by `GET /data-sources` and included in the Evidence Bundle.

Key fields:

- `registry_version`
- `generated_at`
- `safety_disclosure`
- `sources`
- `summary`

Each source includes:

- `id`
- `name`
- `category`: `core_demo`, `public_dataset`, `facility_connector`, `artifact_standard`, `validation_standard`, or `future_extension`
- `role`
- `status`
- `active`
- `writes_allowed`
- `local_only`
- `runtime_network_required`
- optional DOI/license/expected format
- `description`
- `safety_disclosure`

## BenchmarkResult

Generated by `POST /benchmark/run`.

Key fields:

- `benchmark_id`
- `created_at`
- `metrics`
- `trial_table`
- `top_interventions`
- `summary`
- `synthetic_data_disclosure`

Required headline metrics include:

- total trials
- Ghost Beam approvals / small-step approvals / blocks / calibration requests / human-review decisions
- hard-limit violations prevented
- eLog conflicts caught
- average naive projected quality/loss
- average Ghost Beam projected quality/loss
- average OOD before/after calibration
- percent actions modified or blocked
- percent safe actions allowed
